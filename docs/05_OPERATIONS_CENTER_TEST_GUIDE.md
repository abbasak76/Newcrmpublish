# راهنمای آزمون مرکز عملیات — b15

## ورود به سناریوی آزمایشی
1. برنامه را در محیط توسعه اجرا کن و با کاربر دارای مجوز مدیریتی وارد شو.
2. از «مرکز فرماندهی مدیریتی» گزینه «داده آزمایشی» را باز کن و «تولید داده آزمایشی» را بزن. این کار رکوردهای FMCG، مشتریان، کالاها، سفارش‌ها، سه برنامه پخش، برگشتی‌ها، درخواست‌های خرید و پرونده‌های رسیدگی را به State محلی ذخیره‌شونده در IndexedDB اضافه می‌کند.
3. از منو وارد «مرکز عملیات فروش و پخش» شو و تب‌ها را به‌ترتیب بررسی کن: نمای کلی، سفارش‌ها، پخش و ناوگان، برگشتی‌ها، قوانین تجاری، کالا و موجودی، خرید و تأمین، اعتبار مشتری، سودآوری، گزارش‌ها و مغایرت‌ها.
4. برای آزمون چرخه، یک سفارش آزمایشی بساز؛ آن را برای تأیید بفرست؛ قانون اعتباری/حاشیه سود را بررسی کن؛ در صورت نبود هشدار مسدودکننده، آن را تأیید و به برنامه پخش تخصیص بده.
5. برگشتی جدید فقط با علت دسته‌بندی‌شده، مسئول و مهلت ثبت می‌شود. سیستم تسک و پرونده تطبیق می‌سازد؛ تا وقتی سند مالی معتبر متصل نشده، مانده و فروش خالص قطعی را تغییر نمی‌دهد.
6. در تب گزارش‌ها، پوشش بهای تمام‌شده، ظرفیت وزنی، وضعیت وصول و علت برگشت را بررسی کن. «نامشخص» بودن داده بهتر از نمایش سود یا ظرفیت ساختگی است.

## مرز داده آزمایشی
- رکوردهای عملیاتی آزمون با `source: LOCAL_TEST` مشخص می‌شوند؛ داده‌های generated demo دارای شناسه `demo-` هستند.
- داده‌ها در State برنامه و IndexedDB محلی ذخیره می‌شوند؛ این هنوز SQL Server runtime نیست.
- «حذف داده آزمایشی» فقط رکوردهای `demo-` را حذف می‌کند؛ رکوردهای پایه `test-` برای smoke test باقی می‌مانند.
- هیچ اتصال ERP، ارسال سفارش واقعی، فاکتور رسمی، تغییر مانده حسابداری، GPS یا تأیید بارگیری واقعی فعال نیست.
- سیاست‌های این فاز برای آزمون UI و منطق محلی‌اند. اجرای نهایی سیاست‌های حیاتی باید در Backend/ERP یا نقطه کنترل سمت سرور نیز اعمال شود.

## معیارهای پذیرش اولیه
- سفارش بدون مشتری/کالا/تعداد معتبر ساخته نشود.
- قیمت از کاتالوگ seed خوانده شود، نه از ثابت داخل UI.
- سفارش دارای سیاست مسدودکننده تأیید یا تخصیص پخش نشود و دلیل هشدار ثبت گردد.
- وزن/ظرفیت یا سود فاقد داده معتبر، «نامشخص/غیرقابل محاسبه» نمایش داده شود.
- برگشت بدون سند مالی معتبر، فاکتور یا مانده را تغییر ندهد.
- برگشت به مسئول، موعد، تسک، پرونده تطبیق و Audit متصل باشد.
- تکرار اجرای seed رکوردهای `demo-` را تکثیر نکند.
